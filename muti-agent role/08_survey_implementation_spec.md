# 实验问卷系统开发规范

## 1. 问卷触发安排

实验为3周、15个学习Session。所有触发以完成的Session编号为准。实验组与对照组使用相同题目和提交节点。

| 类型 | 包含量表 | 触发Session |
|---|---|---|
| 每两次学习活动 | CSE（3）、PS（7）、NASA-TLX（6） | S2、S4、S6、S8、S10、S12、S14 |
| 每周总结 | CT（5）、AI Reliance（12）、MAI（20）、本周任务体验与AI支持效果、教学行为感知（9）、AI角色识别（1） | S5、S10、S15 |

S10只显示一个合并问卷流程，包含该节点所有待答模块；同一题目不得重复出现。

| Session | 问卷内容 | 题数 |
|---|---|---:|
| S2、S4、S6、S8、S12、S14 | 每两次学习活动问卷 | 16 |
| S5 | 第一周总结 | 56 |
| S10 | 每两次学习活动问卷 + 第二周总结 | 73 |
| S15 | 第三周总结 | 57 |

## 2. 答案选项与评分

| 量尺代码 | 问卷 | 评分输入 |
|---|---|---|
| `likert5` | CSE、MAI、每周任务体验、教学行为感知 | 1非常不同意；2不同意；3一般；4同意；5非常同意 |
| `likert7` | PS、CT | 1非常不同意；2不同意；3比较不同意；4一般；5比较同意；6同意；7非常同意 |
| `frequency5` | AI Reliance | 1几乎从不；2很少；3有时；4经常；5几乎总是 |
| `tlx100` | NASA-TLX | 0–100，步长5，低到高；TLX4端点为“很好→很差” |
| `single_choice` | AI角色识别 | A、B、C、D、E 单选 |

计分：CSE、PS、CT、PL、CM、EV、RU、CU、TU、教学行为IG/MC/FE分别计算各自题项均值。PS1、PS3、PS5按7点评分反向计分，公式 `8 - raw_score`。NASA Raw TLX为6题取算术平均，TLX4按当前“很好→很差”的输入方向保存，不额外反向。每周任务体验和支持效果可保存题项与各小模块均分；角色识别仅保存分类代码。

答题必须保存原始值；计算值和原始值分开存储。量尺和编码在三周及两组之间保持一致。

## 4. 页面与提交行为

1. 学生达到触发Session后，弹出待填写问卷；学生可通过“问卷”入口打开当前待填写表单。
2. 采用模块化分屏形式，提供进度、上一页、下一页、草稿自动保存、确认提交。
3. 使用学生唯一编号与Session作为问卷实例键；每一实例仅允许正式提交一次。刷新、断线后能继续草稿。
4. 周总结问卷中的题干按周次加载：S5使用W1题项、S10使用W2题项、S15使用W3题项。固定量表在不同周次不改变题干。
5. 问卷在完成提交后显示完成状态，已完成问卷不重复自动弹出。

## 5. 后台数据与导出

每条作答至少存储：`participant_id`、`group_id`、`session_id`、`survey_instance_id`、`survey_type`、`question_id`、`raw_value`、`score_value`、`submitted_at`、`survey_version`。

答卷状态分别记录：`pending`、`in_progress`、`submitted`；保留首次打开时间、最近保存时间及提交时间。管理员可按被试、组别、Session、问卷类别导出CSV/XLSX。
